# 产品需求文档 (PRD)：AI 商业情报参谋 (代号：InsightX) - MVP v1.0

## 1. 产品背景
*   **痛点：** AI行业信息爆炸，但90%是技术自嗨或PR通稿（“信噪比极低”）。B端决策者每天耗费大量时间在各平台（公众号、B站、YouTube、播客）筛选信息，却难以直接获得与“商业变现、定价、ROI”相关的有效情报。
*   **目标：** 打造一个高信噪比的“AI商业情报聚合与结构化提取工具”，帮用户把非结构化的行业资讯和视频，转化为可以直接指导商业决策的结构化情报卡片。
*   **现有方案的不足：** 
    *   传统RSS/资讯App：只搬运不总结，阅读成本高。
    *   常规AI总结工具（如Kimi、各类浏览器插件）：单纯压缩字数，缺乏“商业分析师”的视角，无法按结构提取核心商业指标（如落地阻碍、效能提升）。

## 2. 目标用户
*   **用户画像：** AI/SaaS赛道的商业化产品经理、业务负责人、一级市场投资人。具有强烈的目标导向，时间极度宝贵。
*   **核心使用场景：** 
    *   **场景A（碎片化补给）：** 每天早晨通勤的15分钟，快速刷完昨夜今晨的商业情报，寻找当天的业务灵感。
    *   **场景B（深度调研）：** 准备下周的产品定价会议前，搜索近一个月竞品相关API降价或商业模式调整的深度拆解。

## 3. 核心功能
*   **3.1 情报捕手 (Source Ingestor)**
    *   *描述：* 自动化抓取目标站点的文本和视频流信息。
    *   *实现方式（方案一落地）：* 文本直接抓取；视频流通过脚本提取音频，调用Whisper API进行ASR（语音转文字），生成逐字稿。
*   **3.2 商业结构化提取引擎 (Business Insight LLM)**
    *   *描述：* MVP的核心壁垒。对清洗后的长文本/逐字稿进行强结构化Prompt提取。
    *   *用户无感操作，后台执行提取四个维度：* ① 落地场景；② 盈利模式/定价；③ 效能数据(ROI)；④ 落地阻碍。
*   **3.3 极简情报卡流 (Triage UI)**
    *   *描述：* 抛弃传统列表，以卡片形式呈现核心情报，支持滑动分类。
    *   *操作：* 左滑（隐藏/不感兴趣），右滑（收藏至深度阅读库），点击（展开原文对照）。

## 4. 用户旅程 (User Journey)
1.  **进入应用：** 无需注册，首屏直接弹出利益绑定选项：“你最关注的变现赛道是？”（选择：SaaS出海/教育/电商等）。
2.  **获取高潮 (Aha Moment)：** 瞬间生成当天的【高优情报卡片】，直接展示颠覆性技术的商业影响及降本测算。
3.  **信息筛选：** 用户像刷Tinder一样快速滑动卡片（左滑/右滑），系统后台默默记录偏好权重。
4.  **深度下钻：** 遇到高价值的视频转录卡片，点击展开，查看AI梳理的商业逻辑脑图和精准定位到关键发言的原文/原音频。
5.  **目标达成：** 完成今日的商业情报摄入，或者将核心数据一键复制/导出为Markdown，用于自己的工作文档。

## 5. 界面设计 (含 ASCII 原型图)
*   **风格：** 极客、克制、数据密集型。强调空间利用率和视觉层次（利用灰度区分层级）。
*   **配色：** 深色模式为主。
*   **参考产品：** Bloomberg Terminal (专业感) + Tinder (交互效率)。

## 6. 技术方案
*   **前端：** 推荐使用 Flutter 或 React Native 构建跨平台移动端。
*   **后端服务 (基于你的技术栈偏好)：** Python + FastAPI（处理流式数据和并发极其方便，适合跑大模型任务）。
*   **第三方及 AI 服务：**
    *   视频/音频抓取：`yt-dlp` (YouTube), 相关开源解析接口 (Bilibili/微信公众号)。
    *   语音转文字：OpenAI Whisper API (或国内平替如阿里/讯飞的ASR服务，视合规与成本而定)。
    *   核心大模型：Claude 3.5 Sonnet 或 DeepSeek-Coder（性价比较高，结构化遵循能力极强）。
    *   数据库：PostgreSQL (存储关系型数据和用户设置) + Vector DB (如 Pinecone/Milvus，用于后续相似情报推荐，MVP阶段可暂缓)。

## 7. MVP 范围界定
*   **✅ 必须包含 (In Scope):**
    *   微信公众号文章、B站/YouTube 指定高优频道的自动定时抓取。
    *   音频降维提取：视频抽音 -> Whisper 转录 -> LLM 结构化提取流水线。
    *   核心卡片流 UI 与左滑右滑交互。
    *   基于 Prompt 的商业四要素（场景、盈利、ROI、阻碍）提取引擎。
*   **❌ 不包含 (Out of Scope):**
    *   直接读取视频画面的多模态解析（成本过高）。
    *   复杂的用户账号体系（MVP 第一版用设备 ID 或本地存储即可）。
    *   社交分享与评论功能。
    *   全网泛资讯抓取（MVP 只抓预设的 30 个高质量源）。

## 8. 边界情况 (Edge Cases)
1.  **视频无字幕且背景噪音极大（ASR 失败）：**
    *   *处理：* 系统打上“无法解析”标签，不占用 LLM 的 Token，直接将原链接推送给用户并标注“需人工听译”。
2.  **大模型幻觉（捏造了 ROI 数据）：**
    *   *处理：* 在 Prompt 中强制要求 LLM 输出提取依据。UI 层提供一键“溯源”按钮，点击高亮原文/原字幕中的出处。如果大模型无法给出原文片段，则对应字段显示“未提及”，禁止脑补。
3.  **Token 超限（例如 3 小时的播客）：**
    *   *处理：* 后端 Python 脚本按时间戳切片（例如每 20 分钟一段），分别进行摘要后，再交由 LLM 进行二次全局商业逻辑汇总。
